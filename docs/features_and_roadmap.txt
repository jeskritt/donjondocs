DonjonDocs — Features & Roadmap
================================

This file is a quick-scan inventory of what ships today and what is queued.
Authoritative details live in the rest of docs/ and the code itself; this
list is meant for orientation, not specification.


Current features
----------------

Auth & accounts
  - JWT login via HttpOnly access_token cookie; logout clears the cookie.
  - Registration page (gated by ALLOW_REGISTRATION env flag) and rate-limited.
  - bcrypt password hashing.
  - RBAC roles: admin, premium, standard. Standard tier capped at 25 characters.
  - Soft-delete via is_active=False; user rows are never hard-removed.
  - Admin password reset (rate-limited).

Character management
  - Create / edit / delete / list characters, scoped per-owner.
  - Per-rule-system seeding (app/services/character_seeding.py): fresh
    characters get sensible defaults for class entries, saving throws,
    skill proficiencies, and prof bonus.
  - Versioned JSON export and import endpoints (api/characters/{id}/export,
    api/characters/import). Migration chain in app/services/character_io.py
    keeps older exports importable as the schema evolves.
  - Standard-tier character cap enforced via row-locked count
    (no TOCTOU race when creating in parallel).

Sheet rendering
  - Three implemented builders: D&D 5e, Advanced 5e (A5e), Shadowdark.
    SheetStyle also defines UM5, GeneFunk, Carbon — ORM-only; no builder yet.
  - Refreshable card components in app/ui/components/sheet/ (abilities,
    skills, hp, defenses, proficiencies, description, equipment, actions,
    plus features dispatcher → features_abilities / features_magic /
    features_maneuvers).
  - Single _save() write path drives all refresh_fns, so attribute edits
    propagate to dependent cards (skills, defenses, magic DC, actions, ...).
  - AC computation derives base_ac / dex_cap / is_shield from equipped
    inventory; breakdown emitted as view_data['ac_breakdown'].

Rest mechanics
  - Long and short rest applied via pure helpers in
    app/services/character_mechanics.py (no DB, no RBAC).
    character_service.rest_character wraps them with persistence.

Global content
  - Ten Global* tables (class, skill, attribute, weapon, armor, item,
    ability, combat_maneuver, spell, destiny). Seeded rows use
    owner_id IS NULL; user-defined custom rows set owner_id to the user.
  - Auto-ingest on startup: if any of the six core tables is empty and
    a data/ folder is present, app/cli/ingest.py populates them from CSVs.
  - A custom-content "Add ..." flow on the sheet creator and sheet pages.

Admin
  - Admin page lists users, can reset passwords and toggle is_active.

Operations & infrastructure
  - Middleware stack: TrustedHost → SlowAPI rate limit → AuthMiddleware
    → SecurityHeadersMiddleware (CSP / HSTS-when-enabled / etc.).
  - Per-route rate-limit decorators on register and admin password reset.
  - SQLite in dev; PostgreSQL-ready (DATABASE_URL switch). Alembic wired
    but versions/ is empty until the first prod migration.
  - Tests use in-memory SQLite; coverage spans services, routes,
    middleware, security headers, schemas, builders, ingest, character
    seeding and IO migration.


Next / wishlist
---------------

  * CSV loaders for the four newer Global* tables (ability, combat_maneuver,
    spell, destiny) — ORM defs exist but app/cli/ingest.py doesn't read them.
  * Builders for UM5, GeneFunk, Carbon (currently raise NotImplementedError
    from get_builder()).
  * Effects DSL — mage armor, shield, stance effects, etc.
  * Search box at the top of long lists (spells, items, maneuvers).
  * Note-taking surface on the character sheet.
  * UI polish pass.
  * Playwright end-to-end tests against an in-memory SQLite app instance.
  * First Alembic migration in alembic/versions/ ahead of the PostgreSQL move.
